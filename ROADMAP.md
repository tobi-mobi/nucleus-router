## Decisions (changes from SPEC.md)
- 2026-11-23 Build versions (looked up, not from memory): MC 26.2, Fabric Loader 0.20.1, Loom 1.19-SNAPSHOT (resolves 1.19.4), Fabric API 0.161.0+26.2, Gradle 9.8.2, YACL 3.9.7+26.2-fabric, Mod Menu 20.0.1.
- 2026-11-23 Mod id `nucleusrouter`, Java package `dev.nucleusrouter`. `core` / `game` / `platform` are packages in one Gradle project, not separate modules. `LayerRulesTest` fails the build if `core` or `game` import Minecraft/Fabric classes.
- 2026-11-23 YACL is a required dependency (it's in the pack). Mod Menu is optional.
- 2026-11-23 Config tunables added beyond SPEC §2 (estimates, not game facts; user to confirm): `stops.npcInteractionSeconds` 1.0, `stops.crystalPickupSeconds` 0.5, `cost.turnExponent` 1.5 (turn time = turnSecondsAt90 x (angle/90)^exp), `cost.fallbackPingMs` 100, `bombs.fuseSeconds` 3.0 (upper end of 2.5-3 s, safer), `bombs.blastCentre` enum (default: centre of the impact block).
- 2026-11-24 Hypixel Mod API is used **listen-only**: the mod adds a handler but never calls `subscribeToEventPacket` or `sendPacket`, so it causes no extra packets (Hard rule). Location packets arrive only because SkyHanni already subscribes; otherwise tab list, then scoreboard, are used. Ping comes from the vanilla tab-list latency, then the SkyBlock tab "Ping:" widget, then `cost.fallbackPingMs`. The Mod API ping packet is never sent.
- 2026-11-24 SPEC §2.2 change: the Queen's den exit is **not** "scoreboard shows Goblin Holdout". The 3 s timer covers only the Queen's castle in the centre of the den area; the exit condition will be spatial (castle bounds), settled by the [VERIFY] item above before 3.3.
- 2026-11-24 `/nucleusrouter` is an alias of `/nr` in case another mod takes `/nr`. Added `general.chatNotices` (local-only chat lines, default on).
- 2026-11-24 World model (1.4): each voxel stores its *original* block (sticky) and its *current* block, 2 bytes per voxel (~8 KB per 16^3 section). The "original" is upgraded to the most permanent kind ever seen there (air < Hard Stone/placed < respawning < unbreakable), so a gemstone first seen already mined becomes sticky once it respawns. A `placing.placedBlockTypes` block appearing in air is PLACED, not respawning. Fluids are a separate list (`bombs.fluidBlocks`) treated as unbreakable solid. Unseen voxels are UNKNOWN and count as solid. STRUCTURE comes from the structure overlay in milestone 2.
- 2026-11-24 World capture runs on one background thread; the client thread only copies chunk sections. Block changes come from a read-only mixin on `ClientLevel.setBlock` (Fabric has no client block-change event). Saves go to `<game dir>/nucleusrouter/lobbies/<server>.nrw` every 2 min, on world change, disconnect and game close.
- 2026-11-24 Fix after in-game test: block changes are hooked on `Level.setBlock` (client world only), because server-sent changes skip the `ClientLevel.setBlock` override. Changes the client applies while predicting (your own actions) are flagged `byPlayer`, and a block you place is PLACED whatever its type. `placing.placedBlockTypes` is now only a fallback.
- 2026-11-24 Lobby saving kept but made optional (`general.saveLobbies`, default on). The user rarely returns to the same lobby; saving still protects a long setup against a crash or reconnect, and costs nothing when unused.
- 2026-11-24 Etherwarp model (1.5): range counts to where the ray *enters* the target block; the block containing the eye is checked too. The valid aim region is measured by casting real rays at an n x n grid on each target face that faces you (plus a ring just outside each face); size is reported as solid angle and as an equivalent cone width, and the best aim point is the valid direction furthest from any invalid one (its "margin"). Grid size is `etherwarp.aimSamplesPerFace` (default 8). Planning uses sticky solidity (`plannedSolid`), live prediction uses `currentlySolid`.
- 2026-11-24 Rendering (1.6) uses vanilla **gizmos** (`net.minecraft.gizmos.Gizmos`: cuboid stroke/fill, line, text, `setAlwaysOnTop()` for through walls), added from Fabric's `LevelExtractionEvents.END_EXTRACTION`, instead of Skyblocker-style custom pipelines. They use vanilla pipelines, so no raw GL and no custom shaders; shown one frame later, which doesn't matter. All drawing goes through `platform/render/WorldDraw` so this can be swapped if needed.
- 2026-11-24 Automated in-game tests: `./gradlew runClientGameTest` (add `-PnrVulkan` for the Vulkan backend) builds a test scene and saves screenshots to `build/run/clientGameTest/screenshots/`. Code in `src/gametest`, not in the mod jar.
- 2026-11-24 `/nr debug ray` only observes: right-clicks (via Fabric use-item/use-block events, always PASS) while sneaking with an item named "Aspect of the Void/End", and the server's teleport packet (read-only mixin on `handleMovePlayer`). It also measures click-to-teleport delay, which replaces the useless tab-list ping for the cost model.
- 2026-11-24 SPEC §2.3 change: "every non-air block blocks the ray" is not true for torches (and water/lava). Such blocks are class PASS_THROUGH (renamed from FLUID): ignored by the ray and count as air above a landing block. Old configs are migrated (config version 2): eye height 1.54 -> 1.27 if the user never changed it, torches added to the list.
- 2026-11-24 SPEC §2.3 change, generalised: **every block you can walk through (no collision box) is invisible to etherwarp** (`etherwarp.noCollisionPassesThrough`, default on). The set (245 block types) is read from Minecraft's registry at startup (`platform/world/BlockRules`); `etherwarp.rayPassesThrough` is an extra list on top. Fits every in-game result so far: water, lava, torches, grass, flowers; fences with torches are landable.
- 2026-11-24 `/nr calibrate bomb` (1.7): arm, throw one Bob-omb (detected by item name "Bob-omb", observed via use events only). At the throw: world snapshot + predicted landing (straight up to `throwRange`, then straight down; walk-through blocks ignored like for etherwarp). Blast = non-player block changes to air within 20 blocks of the predicted centre, collected for 1.5 s after the first one. Analysis tries ball / cube / diamond shapes around 3 candidate centres and reports the best fit (agreement = overlap of predicted vs real removed blocks), the model's error, and breakable survivors. Report JSON in `nucleusrouter/calibration/`. A vanilla explosion packet, if Hypixel sends one, is recorded too.
- 2026-11-24 `/nr dump` writes `nucleusrouter/dumps/<lobby>-<time>.nrw` (same format as lobby saves) + `.json` (settings, location, lobby). The plan will be added in milestone 3.
- 2026-11-24 Bomb model after 6 measured throws: radius 7 ball, direct hit centred on the block hit, 32-block straight range then drop, dropped bomb centred `bombs.dropCentreBlocksAbove` (1) above the landing block. A unit test replays the real throws 4 and 5 and reproduces both measured centres exactly. New config: `hollows.nucleusSpawnX/Y/Z`, `bombs.flightBlocksPerSecond`, `bombs.dropCentreBlocksAbove` (config version 4 migrates old untouched defaults).
- 2026-11-24 Structures (2.1): found from entity **custom names** (armour-stand labels, named mobs; real players are skipped), matched as whole words against config lists `structures.*Names`. Evidence order: manual (`/nr structure set`) > NPC name tag > scoreboard area (rough box of where you stood). Mines of Divan keeps up to 4 keeper anchors and uses their average; every other structure has one anchor (a moving Bal is averaged). "Goblin Holdout" is not used as a King Yolkar hint (it covers a whole quarter). Saved per lobby in `nucleusrouter/lobbies/<server>.structures.json` with the same new-lobby check as terrain. Text-display entities are not read yet; add them if a name tag turns out to be one.
- 2026-11-24 User request: the Queen's den and Khazad-dûm should be marked at their **crystal** (Bal's fight is done standing on the Topaz crystal), not at an NPC. Waiting for `/nr inspect` output to recognise the crystals; until then use `/nr structure set queen|khazad` there.
- 2026-11-24 Wishing Compass (2.2): after a right-click on an item named "Wishing Compass", every particle the server sends within `compass.captureSeconds` (3 s) and `compass.captureRadius` (40) is collected; per particle type a line is fitted (principal axis), and the straightest one is the trail (so the particle type doesn't have to be known; `compass.particleTypes` can restrict it). Lines are crossed by weighted least squares; the weight is the direction error at that distance. Shown: orange lines, magenta estimate with a 95% radius, cyan "use a compass here" spot (60 blocks to the side for 1 line, then 0.7 x the distance, 30-100) until the radius is below `compass.goodRadiusBlocks` (10). Lines that disagree (different targets) are flagged. Lines reset on a new lobby, not saved.
- 2026-11-24 Structures can also come from **Skyblocker's** Crystal Hollows waypoints (read-only reflection on `CrystalsLocationsManager.activeWaypoints`, checked against Skyblocker 6.11.0+26.2; does nothing if missing or changed). They rank below crystal and name tag (Skyblocker's positions come from its compass solver, chat coordinates and other players, so they're approximate). Our own compass solver stays as a backup. `structures.useSkyblocker` (default on).
- 2026-11-24 Queen's den and Khazad-dûm are marked at their crystal's **barrier box**: every 5 s, when you are in their area, near Bal or near Skyblocker's waypoint, the remembered terrain within 48 blocks is searched for clumps of barriers (touching, diagonals included); the biggest clump with at least `structures.crystalBoxMinBarriers` (20) is the box. Works before the crystal mission is done too (empty box).
- 2026-11-24 Less clutter: an optional mixin (`@Pseudo`, `require = 0`) into Skyblocker's `CrystalsLocationsManager.extractRendering` skips drawing chosen Skyblocker waypoints (`structures.skyblockerWaypoints`: SHOW / HIDE_RUN_STRUCTURES (default) / HIDE_ALL). Skyblocker's own on/off switch can't be used for this: it also stops Skyblocker collecting and sharing locations. Skyblocker is a compile-only dependency (Modrinth `skyblocker-liap` v6.11.0+26.2); without Skyblocker the mixin just logs one 'class not found' warning.
- 2026-11-25 Structure shapes (2.3): `/nr capture <name> [radius]` saves the cube around a structure's anchor block (default radius 40) to `nucleusrouter/templates/<structure>-<lobby>-<time>.json.gz` (palette + run-length data, original/sticky blocks). Orientation = compare a capture from another lobby against the current world for 4 rotations x mirror and anchor shifts of +-2, counting only "distinctive" blocks (not air, stone, ores, gemstone glass, fluids, barrier, bedrock); confident if best >= 60% and >= 15 points ahead. Runs automatically for found structures (every 10 s, up to 6 tries per lobby). Zones are boxes relative to the anchor block in template orientation (`structures.zones`, key -> 6 ints), turned with the detected orientation; drawn as red boxes (not through walls). A bomb fizzles if any block centre within the blast radius lies in the zone box. "Precise scanner": exact positions come from name tags, crystal boxes and manual set (2.1); searching the world for a template without an anchor is left out until real templates show it's needed.
- 2026-11-25 Exploration coverage (2.4): grid of 4x4-block columns over the Hollows bounds. "Visited" = within `exploration.visitRadius` (48, an estimate of name-tag range) of you, marked once a second; "loaded" = any chunk received (a loose upper bound, render distance makes it grow fast). The swap rule in 2.5 should use **visited**. `/nr explored [map]` shows both, the nearest unexplored stretch (direction + distance) and a 20x20 chat map with found structures. Saved per lobby (`<server>.coverage.json`).
